## 0. 이번 개편의 한 문장

여정은 **"퇴근길에 어디 갈까"를 알려주는 앱이 아니라, "오늘 몇 분을 쓸 수 있고, 그 시간 안에 어디서 쉬고, 몇 시에 돌아오면 되는지"를 정해주는 앱**으로 바뀐다.

기존 제품은 발견(장소)과 기록(리뷰·리포트)을 먼저 만들었다. 새 제품은 **결정과 실행**을 먼저 만들고, 기록은 실행의 부산물로 둔다.

## 1. 제공 가치 재정의

### 1.1 한 문장 가치

> **"오늘 쓸 수 있는 15분으로, 한 정거장 옆에서 회복하고, 제시간에 돌아온다."**

### 1.2 기존 가치와 새 가치

| 구분 | 기존 | 새 정의 |
|---|---|---|
| 중심 질문 | "이 역 근처에 뭐가 있지?" | "지금 내려도 되나? 몇 분 쓸 수 있나? 몇 시에 돌아오나?" |
| 핵심 대상 | 장소 | **시간** |
| 성공의 단위 | 장소 조회·저장·리뷰 | **복귀까지 완료된 회복 세션** |
| 실패의 순간 | 장소가 없음 | **내렸는데 시간이 모자라거나, 돌아오는 게 부담스러움** |
| 경쟁 상대 | 지도 앱의 주변 검색 | 지도 앱 + "그냥 집에 가는 선택" |
| 기록의 역할 | 성과 증명(리포트·챌린지) | 다음 결정을 돕는 **맥락 기억** |

### 1.3 세 기둥

1. **회복 예산(Recovery Budget)** — 오늘 쓸 수 있는 추가 시간을 분 단위로 정한다. 앱은 이 예산을 넘지 않는 후보만 제안한다.
2. **복귀 보장(Return Check)** — 도보 왕복, 체류, 대기, 배차 간격을 합산해 복귀 시각을 계산하고, 여유가 3분 미만이면 "빠듯함"을 표시한다. 막차·운임 주의도 함께 안내한다.
3. **회복 기록(Recovery Log)** — 어디서 얼마나 쉬었는지, 예산을 지켰는지만 남긴다. 리뷰는 선택이다.

### 1.4 하지 않을 것

- 명소·맛집 랭킹, 다수 장소 비교, 여행 코스 추천
- 연속 출석, 방문 횟수 목표, 손실을 강조하는 알림
- 리뷰 작성을 기본 동선에 넣는 것
- 위치 상시 추적, 자동 방문 인증
- 검증되지 않은 "조용함·무장애" 라벨

### 1.5 포지셔닝 문장

> 지도는 목적지까지의 길을 알려준다. 여정은 **돌아오는 시간**까지 알려준다.

## 2. 사용자와 상황

### 2.1 1차 타깃

서울 지하철로 주 3회 이상 통근하고, 퇴근길에 10~30분의 여유가 생기는 직장인. 특히 **도착역 근처에서 한 정거장 먼저 내리는 것이 물리적으로 가능한 구간**을 쓰는 사람.

### 2.2 세그먼트

| 세그먼트 | 상황 | 제공 가치 | 우선순위 |
|---|---|---|---|
| 여유형 | 퇴근 후 일정이 유연, 주 1~2회 20~30분 여유 | 긴 우회 후보, 앉을 곳 중심 | 1 |
| 짧은형 | 10~15분만 남음, 곧장 귀가해야 함 | 역 3분 거리, 포장 가능한 곳 | 1 |
| 환승형 | 환승역에서 대기 시간이 생김 | 환승 대기 활용(개찰구 밖 출입 고려) | 2 |
| 기록형 | 쉰 곳을 남기고 싶음 | 회복 로그, 다시 갈 곳 | 3 |

### 2.3 Jobs to be done

- "오늘 15분 있는데, 내릴 만한 곳이 있나?"
- "내렸다가 몇 시에 돌아오면 되지?"
- "지난번에 좋았던 곳에 오늘 다시 들를까?"
- "이번 주에 나는 얼마나 쉬었나?"

### 2.4 안티 페르소나

서울 관광객, 등산·장거리 걷기 이용자, 여러 장소를 비교해 코스를 짜는 사용자, 리뷰 탐색이 목적인 사용자.

## 3. 핵심 경험 설계

### 3.1 회복 루프

    ① 예산 확인 (오늘 15분)
        ↓
    ② 후보 1개 + 대안 2개 (예산 내, 복귀 시각 포함)
        ↓
    ③ 내릴지 결정 ("내릴게요" / "오늘은 그냥 갈게요")
        ↓
    ④ 실행 (복귀 모드: 남은 시간, 다음 열차, 복귀 버튼)
        ↓
    ⑤ 복귀 (제시간 / 지연)
        ↓
    ⑥ 1탭 기록 → 다음 주 결정에 반영

이 루프에서 이탈이 가장 잦은 지점은 ②→③이다. 그래서 후보는 **1개를 크게, 2개를 작게** 보여주고, 판단에 필요한 숫자(도보 분, 총 추가 분, 복귀 시각)를 카드 안에 고정한다.

### 3.2 시간 예산 모델

    추가 시간 = 도보 편도 × 2 + 체류 + 대기 여유
    대기 여유 = max(3분, 배차 간격 ÷ 2)
    후보 자격 = 추가 시간 ≤ 예산 − 3분(안전 여유)

예시: 예산 15분, 도보 편도 4분, 배차 5분 → 8 + 4 + 3 = 15분 → **후보 부적합**(여유 0분). 앱은 이 후보를 "빠듯해요"로 낮추고, 3분 거리 후보를 먼저 보여준다.

체류 기본값은 예산에 따라 자동 제안한다(10분 예산 → 2분, 20분 → 6분, 30분 → 15분). 사용자는 상세에서 ±5분 조정할 수 있다.

### 3.3 복귀 보장 규칙

- 복귀 시각을 항상 "HH:MM"으로 노출한다. "곧 돌아오세요" 같은 모호한 표현을 쓰지 않는다.
- 여유 3분 미만: 주황 상태 "빠듯해요 · 대기 없이 바로 복귀"
- 여유 0분 이하: 빨강 상태 "지금 출발해야 해요" + 후보를 기본 목록에서 내림
- 막차 30분 이내: 막차 시각과 환승 주의를 카드에 고정
- 운임: 개찰구 재진입이 필요한 후보에는 "재승차 필요" 태그. 추가 운임 여부는 단정하지 않고 "운임 규정 확인" 링크

### 3.4 기록의 원칙

기록은 **의사결정 데이터**다. 리뷰가 아니다. 저장 항목은 5개 이하: 장소, 날짜, 예산, 실제 체류, 만족(좋았어요/보통/아쉬움). 텍스트는 선택.

## 4. IA

### 4.1 최상위 구조

하단 탭 4개. 실행 중에는 탭 위에 **복귀 모드 바**가 고정된다.

    여정
    ├─ 오늘 (기본 탭)
    │   ├─ 예산 카드
    │   ├─ 추천 후보 1 + 대안 2
    │   ├─ 후보 비교 시트
    │   ├─ 장소 상세
    │   └─ 복귀 모드 / 결과 기록
    ├─ 노선
    │   ├─ 통근 구간 요약
    │   ├─ 경로 편집(출발·도착·직전 역·방향)
    │   ├─ 역 상세(그 역의 후보)
    │   └─ 탐색·검색
    ├─ 기록
    │   ├─ 이번 주 리듬
    │   ├─ 회복 세션 목록 / 하루 상세
    │   └─ 저장한 곳 · 다시 갈 곳
    └─ 나
        ├─ 프로필(닉네임)
        ├─ 알림·요일·시간
        ├─ 데이터(내보내기·삭제)
        └─ 정보(버전·약관·오픈소스)

### 4.2 네비게이션 규칙

- 앱 진입은 항상 **오늘**이다. 예산이 비어 있으면 기본 예산으로 시작한다.
- 상세·검색은 탭을 유지한 채 스택으로 올린다(하단 탭 유지).
- 복귀 모드 중에는 뒤로 가기로 탭 이동을 막고, 상단 "복귀" 버튼으로만 종료한다.
- 저장·방문·리뷰는 최상위 탭이 아니라 오늘과 기록 안의 동작으로 들어간다.

## 6. 핵심 플로우

### 6.1 첫 실행 (목표 90초)

    1) 가치 한 줄 + "기기 저장" 안내
       [시작하기]
    2) 출발역 → 도착역 (검색, 최근 역 우선)
       방향 자동 표시: "○○ 방면"
    3) 평일 퇴근 시간 (18:00 기본) + 알림 켜기/끄기
       [여정 시작]
    → 오늘 화면, 기본 예산 15분, 직전 역 후보 즉시 계산

예외: 역 검색 실패 → 직접 목록에서 선택. 그래도 없으면 "경로는 나중에 설정" 후 홈 진입(후보 없음 상태).

### 6.2 매일 퇴근 결정 (핵심 플로우)

    1) 알림 또는 앱 열기
    2) 오늘 카드: "오늘 15분, 한 정거장 쉬어갈까요?"
       - 기준: 도착역 직전 역
       - 후보 1: 가장 가까운 곳 (도보 3분, 총 12분)
       - 복귀 시각: 19:07
       [내릴게요] [다른 곳 보기] [오늘은 그냥 갈게요]
    3) [내릴게요] → 상세 확인(운영시간·재승차·거리)
       [지금 출발] 
    4) 복귀 모드 진입

분기:
- 후보 없음 → "이 역엔 적합한 곳이 없어요" + 인접 역 2개 제안 + 예산 늘리기

### 6.3 실행과 복귀

    복귀 모드 (상단 고정 바)

      다음 열차 19:05, 19:10 (도착역 방면)

## 8. 데이터와 기술

### 8.1 로컬 모델

| 엔티티 | 필드 |
|---|---|
| CommuteProfile | id, originStationId, destStationId, direction, days, departWindow, defaultBudget |
| DetourSession | id, placeId, stationId, plannedBudget, plannedReturnAt, startedAt, returnedAt, actualStayMin, outcome, rating |
| SavedPlace | placeId, savedAt, lastVisitedAt, visitCount |
| PlaceSignal | placeId, quietScore, hasSeat, orderRequired, verifiedAt, source, reporterCount |
| TimetableSegment | stationId, lineId, direction, firstTrain, lastTrain, headwayByPeriod |

### 8.2 시간표 데이터

복귀 보장의 핵심이다. 초기에는 **정적 시간표(배차 간격·첫차·막차)** 로 시작하고, 실시간 도착 정보는 도입하지 않는다. 실시간 API는 키·쿼터·장애 리스크가 크고, 3분 여유 계산에는 정적 배차 간격이면 충분하다. 데이터 버전과 기준일을 화면에 표시한다.

현재 저장소에는 시간표 자산이 없다. 지하철 그래프(capitalStations, subwayPos, 노선별 인접 역)만 있으므로, 배차 간격과 막차 시각은 **노선별 수동 테이블로 새로 확보**해야 한다. 확보 전에는 5분 기본 여유를 쓰고 다음 열차 시각은 표시하지 않는다(추정치를 사실처럼 보여주지 않는다). 노선 23개의 평일 배차·막차는 공개 운행 시각표로 1회 구축하면 갱신 주기가 길어 유지 비용이 낮다.

### 8.3 후보 계산 순서

    1) 직전 역 좌표 조회
    2) 반경 300 → 600 → 900m 순차 조회 (실제 제한은 예산 필터)
    3) 최근접 역 귀속 대신 "이 역에서 도보 N분" 계산
    4) 추가 시간 계산 → 예산 필터
    5) 정렬: 여유 시간 → 도보 거리 → 검증 여부
    6) 상위 1 + 대안 2

장소를 한 역에만 귀속시키던 규칙은 폐기한다. 같은 장소가 인접 역 후보에 나올 수 있고, 카드에 "○○역에서 도보 4분"을 명시한다.

### 8.4 알림·위젯

- 퇴근 시간 15분 전 1회: "오늘 15분, 한 정거장 쉬어갈까요?"
- 실행 중 체류 70% 1회
- 알림은 사용자가 켠 요일·시간에만. 하루 1회 상한
- 위젯: 예산·후보 1개·[내릴게요] (P1)

### 8.5 오프라인

- 지하철 그래프 내장
- 내 구간 주변 장소 캐시(최근 14일)
- 캐시 사용 시 "오래된 정보" 배지와 확인 시점
- 네트워크 실패 시 후보 계산은 캐시로 계속, 운영정보만 잠금

## 9. 지표

### 9.1 North Star

**주간 완료된 회복 세션 수** (복귀 완료 + 기록 저장 기준). 조회·저장은 보조 지표다.

### 9.2 퍼널

| 단계 | 지표 | 초기 기준 |
|---|---|---|
| 진입 | 오늘 화면 도달 | 설정 완료자의 90% |
| 판단 | 후보 카드 노출 | 후보 있는 세션 100% |
| 결정 | "내릴게요" 탭 | 40% |
| 실행 | 복귀 모드 진입 | 탭 대비 70% |
| 완료 | 복귀 완료 기록 | 진입 대비 60% |
| 반복 | 14일 내 재실행 | 완료자의 50% |

### 9.3 가드레일

- 지연률(예산 초과 복귀) 15% 이하
- 후보 신고("운영 안 함") 5% 이하
- 알림 끄기 비율 20% 이하
- 첫 설정 이탈 10% 이하

### 9.4 실험

| 실험 | 가설 | 측정 |
|---|---|---|
| 예산 기본값 15 vs 20분 | 20분이 실행률을 높인다 | 탭률, 완료율 |
| 후보 1개 vs 3개 동등 노출 | 1개가 결정을 빠르게 한다 | 결정 시간, 이탈 |
| 알림 문구 "15분 있어요?" vs "쉬어갈까요?" | 구체적 시간이 실행을 높인다 | 알림→실행 |
| 복귀 모드 유무 | 복귀 모드가 지연을 줄인다 | 지연률 |

## 10. 디자인 원칙

- **숫자가 주인공**: 예산·복귀 시각·도보 분은 display 타이포로 크게. 설명 문장은 줄인다.
- **결정은 한 화면에서**: 오늘 화면에서 후보 선택과 실행이 끝난다.
- **경고는 색+문구 동시**: 주황/빨강만으로 의미를 전달하지 않는다.
- **Material 3 역할 기반 색**: primary는 브랜드 블루(#0D70FF), surface/outline은 기존 토큰 유지. 경고는 error 역할, 여유는 tertiary.
- **8dp 그리드, 20dp 좌우 여백 유지**, 카드 모서리 16dp(패널), 8dp(리스트 카드).
- **접근성**: 48dp 터치, 본문 16sp 이상, 대비 4.5:1, 동적 글꼴 200%에서 카드 깨짐 없음, 복귀 타이머는 5분 단위 음성 안내.
- **모션**: 복귀 모드 진입 시 1회 슬라이드, 그 외 반복 애니메이션 금지.

## 12. 리스크와 결정 기록

| 리스크 | 영향 | 대응 |
|---|---|---|
| 시간표 데이터 미확보 | 복귀 보장 신뢰 붕괴 | 배차 간격 미확보 시 5분 기본값 + "예상" 표기, 막차 경고는 데이터 확보 후 |
| 장소 후보 부족 | 핵심 화면 빈 상태 | 소수 구간 우선, 인접 역 제안, 억지 채움 금지 |
| 300m 반경으로 후보 과소 | 실행률 저하 | 반경 상한(600~900m) 유지 + 예산 필터로 제한, 부족 시 인접 역 제안 |
| 재승차 운임에 대한 오해 | 불만·신뢰 | "재승차 필요" 태그 + 규정 링크, 단정 금지 |
| 복귀 모드가 부담으로 작동 | 이탈 | 5분 더, 종료 버튼 상시, 실패 표현 금지 |
| 과감한 개편으로 기존 기록 손실 | 신뢰 | 마이그레이션·내보내기 우선 |

결정 필요(권고안 포함):

1. **예산 기본값 15분** — 10분은 너무 짧고 20분은 부담. 파일럿에서 비교.
2. **직전 1개 역만 기본 노출** — 인접 역은 "다른 역에서 내리기"로 진입.
3. **실시간 도착 정보 미도입** — 정적 배차 간격으로 시작, 지연률 15% 초과 시 재검토.
4. **리뷰 기능 유지하되 기본 동선에서 제거** — 기존 데이터는 열람·내보내기 보장.
5. **위젯은 P1** — 실행률이 확인된 뒤 투자.

## 13. 요약

여정의 새 제품은 **시간을 다루는 앱**이다. 사용자는 장소를 고르러 오지 않고, "지금 내려도 되는지"를 확인하러 온다. 그래서 IA의 중심은 오늘 화면이고, 기능의 중심은 예산 계산과 복귀 보장이며, 성공의 단위는 조회가 아니라 **복귀까지 끝난 회복 세션**이다.
